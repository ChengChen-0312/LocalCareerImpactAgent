# RAG 归因与分析规范修正

2026-09-06，Australia/Melbourne。本记录单独评价新增政府数据和归因修正；不把旧版本的五次稳定性通过计入本版本。

**当前结论：可用于有人核对引用的 localhost demo。** 最终固定源码下，中英文普通资料各一次真实流程通过，背景职责引用核读通过；未建立本版本的五次重复或极端输入稳定性，也未证明审核理由和职业预测全部正确。

## 修正范围

此前一份真实中文报告完成 9/9，但六条声明全部标为 RAG，包括未来影响和行动建议；当前职业职责不足以支持这些结论。风险说明也重复了职业概述。仅增加提示没有在该次运行中解决问题。

本轮保持原有九阶段、每阶段最多两次尝试、输出预算、共享 Metal 锁以及 `MvpReportV1` 存储/UI 合同。30B 仍决定所有声明、建议采纳与报告文字；4B 只提出审核建议。没有后端改写声明类型或补写结论。

- 从同一冻结快照中按职业职责、AI 影响、就业市场分别选取最多 4、2、2 段。主题先过滤，再执行已有稀疏/向量排名；普通未分类语料保留通用路径。目录覆盖不等于内容相关或证据支持。
- draft/F2 生成四条核心声明，依次为一条来源背景、两个时间范围的推演和一条行动建议；确认的个人资料仍提供给模型作场景上下文。背景事实不携带模型自己的时间范围或影响等级；RAG 声明从本次冻结的实际片段／事实 ID 中选择一个引用，不接受来源元数据。F2 保留草稿的完整声明 ID 集合。这是 demo 生成范围的收窄，存储合同仍兼容原有报告。
- F3 的职业概述绑定 RAG 背景声明，未来情景和任务影响绑定相同时间范围的推演，行动绑定建议，机会绑定推演/建议，风险绑定推演并与职业概述区分。相关事实可作为 supporting claims，不会改变推演的来源标签；没有强制模型给不相关的预测挂上背景引用。
- 短规范位于 [产品 Skill](../../src/localcareerimpact/agent/skills/career-impact/SKILL.md)，由应用实际读取并加入草稿、三项审核及 F1/F2/F3 提示。F1 现在同时拿到冻结证据，能够核对审核者的解释。生成约束与现有阶段/完整校验共同执行这些边界。
- 错误仍保留阶段、attempt、封闭类别、结构位置和 token 指标。引用说明改为“引用的证据”，不由程序宣称“证据支持声明”。
- 本轮真实失败还暴露出审核生成形状与固定输出预算不匹配：三条建议原先各允许 4,000 字，引用数组没有长度上限。现仅在生成 schema 中要求每条为最多 180 字的完整单句、最多三个 affected claims 和两条关键证据；模型自行压缩与选择，不在后端裁切，不增加预算。

原件、转换口径、版本和完整哈希见 [政府数据说明](government-data.md) 与 [清单](au-government-data-manifest.json)。旧原件和快照保留。JSA 就业预测尚未纳入生成式 AI 等新技术影响，其固定基期也不等于报告的滚动时间范围。[JSA 就业预测口径](https://www.jobsandskills.gov.au/data/employment-projections)

三项有限检索观察覆盖中文会计、中文护士、英文软件工程师。职业与职责查询合并后，通用英文主题词曾让中文 AI/就业结果偏离目标；该失败保留在 `retrieval_history`。改用确认职业检索 AI/就业背景，并为职责另留配额后，职业首条均匹配目标，三类目录各有返回。部分后续结果仍是邻近职业或一般研究段落，因此不能把 4/2/2 配额当成相关率。

第一轮真实中文会计流程在安全审核失败，用时 270.851 秒；两次都是 `truncated`、2,048/2,048 tokens，0 份报告。草稿、证据审核、边界审核均已通过；F1/F2/F3 没有执行，不能将该失败归因于 F2。诊断在读报告前及退出时保存；模型停止、上传残留 0，旧会话/消息/报告行未改变。完整失败结果保留在 [安全记录](grounded-demo-validation.json)。

已据此收紧上述审核生成形状。两次截断证明输出触及预算；由于安全记录不保留原始失败生成文本，不能断言具体是哪一个文本或引用字段耗尽预算。修正后的真实 API 与内容核读结果另列，不用后续通过覆盖本次失败。

第二轮同版观察：中文会计 238.967 秒、9/9、1 份报告、全部阶段首次通过，但 8 条声明只有 profile／推演／建议，0 条 RAG、0 个引用。职业概述还混入未由用户提供的自动化判断，因此人工内容核读为 **FAILED**，不能用该次结构通过声称 RAG 报告合格。随后英文软件工程师在 draft 两次 `EVIDENCE_REFERENCE`，路径均为 `claims[3].evidence_refs`，分别 1,868／1,801 tokens，用时 113.335 秒，0 份报告；不是截断。

这两例促成下一步收紧：至少一条真正可引用的 RAG 背景、职业概述绑定 RAG、个人资料不再作为无引用背景声明的替代路径，生成引用仅可选择冻结的 passage／fact IDs。它们不替代原始证据支持性的核读，也没有后端重标旧报告。

第三轮同版观察：中文会计 251.453 秒、9/9，生成 2 条 RAG／2 条情景／1 条建议，4 条引用可读；但人工核读与独立复核发现 ANZSCO Accountants、OSCA Bookkeeper、Management Accountant 短缺和 Finance Managers 预测被混用，两个 RAG 声明都有扩大范围或无关引用，内容仍为 **FAILED**。英文在 F1 两次 `SUGGESTION_BINDING`，各 605 tokens，用时 213.523 秒，0 报告；三组审核确实各有三条建议，无法从安全记录推断具体错写了哪个 ID。

随后把已知 F1 建议 ID 和数组长度绑定到生成 schema，只让 30B 决定采纳／拒绝和理由；每条 RAG 只选一条实际内容证据，职业概述仅绑定其主要职责声明。共享规范要求保留职业名称、代码、分类版本、年份和指标口径，禁止把子职业数据外推到整个职业或个人，也不能把无短缺解释为需求稳定。最终版本结果另列。

第四轮同版观察：中文会计 357.133 秒、9/9，生成 1 条 RAG／6 条情景／1 条建议、1 条引用；F1 首次到达 1,536 tokens 后截断，第二次恢复。虽然引用不再混用职业，但 RAG 声明把用户提供的月末结账和发票核对并入官方职业职责，uncertainty 又称内容基于用户自述，人工内容核读仍为 **FAILED**。英文草稿两次 `CLAIM_BINDING`，路径均为 `claims`，分别 2,499／2,151 tokens，用时 129.764 秒、0 报告。

据此在已有 4–8 条声明的前四个位置固定背景、两个时间范围的情景和建议，由模型填写内容并保留 F2 原始 ID 集合；规范加入来源职责与用户额外职责的分离示例，证据审核逐项核对唯一引文。F1 理由在原预算内限为最多 96 字符的完整短句。以上均为生成约束，不裁切或重写模型结果；仍需真实内容核读确认效果。

第五轮同版观察：中文 281.903 秒、英文 247.500 秒，两例均 9/9、全部首次通过，分别保存 1 份报告，1／3 条引用可读取。中文职业概述与职责原文吻合，但底层 RAG 声明仍增加唯一引文没有的 OSCA 分类；英文核心职责与短缺背景吻合，额外的 RAG 声明却用仅列 specialisations 的片段支持用户的缺陷调查和自动测试职责。两例内容核读均为 **FAILED**。英文部分未来栏目正文也只重复当前职责，变化主要出现在不确定性说明中。

最终把 demo 生成范围收窄为四个基本声明，仍提供八段检索上下文，由模型把两个情景展开为多条任务影响与行动；这会减少可选背景声明数量，不是更广的数据覆盖证明。另对 RAG 文字明写的 ANZSCO／OSCA 标识增加窄检查：唯一引文没有该标识时拒绝并由 30B 在已有重试中修订。该检查不能识别同一分类中写错版本，也不证明一般语义支持。当前职责摘要不必重复代码／版本串，准确元数据保留在引用原文；涉及数量或短缺时仍保留决定结论范围的职业、年份和指标。

## 适用边界

这些约束可以拦截声明类型、时间范围、栏目绑定和明显重复等问题，不能证明任意中英文改写都被英文原文蕴含，也不能验证职业预测的未来准确性。演示时应打开引用，区分官方背景、模型情景和建议；缺失或不匹配的细分职业资料仍可能影响质量。

Task 7 与 Task 8 的本地软件已由此前记录交付；真人麦克风与远程演示仍未实测。本轮没有新增功能面、测试源码或运行依赖，也不据此把原完整人工验收改为全部通过。
