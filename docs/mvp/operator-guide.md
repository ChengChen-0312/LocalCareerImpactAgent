# 本地演示操作指南

先完成本地使用，再按需要单独开启远程演示。这里只说明当前 MVP 的操作；已有的大型 Task 4 设计不属于本启动流程。

## 首次准备

使用项目锁文件对应的 Python 3.12 环境、Node/npm，以及已经下载到本机的模型。依赖安装需要网络时，应在演示前完成；启动器不会下载模型，也不会安装 cloudflared。

在项目根目录准备依赖：

```bash
uv sync --locked
uv sync --locked --project environments/qwen
uv sync --locked --project environments/embedding
uv sync --locked --project environments/asr
npm --prefix web ci
```

上述命令是准备步骤，不是验收通过记录。若锁文件或安装步骤失败，先处理该问题再启动。

首次把 `config/users.csv.example` 复制成 `config/users.csv`，把 `config/models.local.json.example` 复制成 `config/models.local.json`。已有本地配置时不要覆盖。

账户 CSV 的第一行必须保持 `username,password,enabled`。为每个演示账户设置不同的用户名和自己的密码，启用时把 enabled 写成小写 `true`，停用时写成 `false`。至少启用一个账户；用户名不能重复。需要维护知识库时，另外配置一个启用的 `admin` 账户。不要继续使用示例密码，不要把实际账户 CSV 发给他人或提交到 Git。

模型配置必须保留 `qwen30b`、`qwen4b`、`embedding`、`whisper` 四个键，把每个值改成对应的本地模型目录。启动器会检查目录和运行环境是否存在；是否能真正加载模型，需要后面的就绪检查确认。实际模型路径不写入验收记录。

## 启动和停止本地入口

```bash
bash scripts/run-local.sh
```

启动器先检查 CSV、模型配置及本地运行环境。若 `web/dist/index.html` 不存在，会构建网页；若前端依赖也未准备，会先执行锁定依赖安装。构建日志和启动问题输出到终端错误流，正常标准输出只有本地网址。

打开 `http://127.0.0.1:8000` 并登录。模型加载需要时间；出现网址只是开始启动，不能作为两个模型已就绪的证据。`/api/health` 中 `database`、`qwen30b`、`qwen4b` 都为 `ready` 才表示本次服务可开始分析。不能连接时先等加载完成，再检查终端错误。

本地应用在当前终端前台运行。结束时按一次 Ctrl+C，等待应用清理正在执行的任务和模型进程。不要连续强制退出。固定使用一个服务进程，不要额外添加 `--reload` 或多个 Uvicorn workers，也不要同时启动本地和远程脚本。

修改前端源文件后，重新运行 `npm --prefix web run build`；启动器只会补建缺失的构建结果，不会自动判断已有结果是否过期。

## 添加知识并生成报告

本机已于 2026-09-06 补入澳洲政府职业、就业预测、短缺和 AI 研究资料，并配置了支持中英文查询的本地检索模型。覆盖范围、年份和更新位置见 [澳洲政府知识库](government-data.md)。2026-09-07 的私有仓库更新包含数据库压缩备份，需按 [恢复说明](../../data/database/README.md) 手动恢复后使用已有快照。模型权重和原始知识文件仍需另行准备；检索模型须与快照指纹匹配。

把准备好的 PDF/TXT 知识材料放入 `data/knowledge/inbox/`，或使用 `admin` 账户在知识库页面上传文件。点击重建并等待成功，查看当前快照；仅上传文件还不表示已经纳入检索。

需要分别补充职业职责、AI 影响和就业市场资料时，可在知识库下使用 `occupations/`、`ai-impact/`、`labour-market/` 子目录。分析会从同一冻结快照中分别选择最多 4、2、2 段；职业用于寻找对应资料，职责用于补充任务背景。目录表示管理员指定的资料主题，不保证每条召回都相关。普通未分类文件仍可参与职业查询；完全未分类的知识库沿用原有通用检索。新建或移动目录后需要重建，某类资料缺失时不会用其他类资料冒充覆盖。

分析规范保存在包内 `src/localcareerimpact/agent/skills/career-impact/SKILL.md`，由应用启动时读取并加入 30B 与审核角色的提示，无需在 Codex 中另行安装 Skill。修改规范后需重启应用。规范要求区分来源事实、未来情景和行动建议；代码同时检查声明类型、时间范围和栏目引用。来源片段是否真正支持模型措辞仍需要核读，规范和结构校验不能证明所有预测正确。

普通账户创建会话，输入职业资料或上传材料。报告语言优先按本次消息中明确的要求选择，例如“请用中文回复”；一般对话按输入语言选择。只上传附件，或同时使用首页默认示例问题时，若正文语言可判定，则按同次上传材料选择语言；旧附件不会覆盖新的对话语言。文字、PDF、TXT、上传音频和麦克风分别需要在验收记录中实际演示。麦克风需要浏览器许可，由用户点击开始；录完后停止并提交。

检查生成的资料卡，修改误识别内容，然后点击确认并分析。未确认前不应启动分析。运行期间查看阶段进度；页面刷新或事件流断开不应被当作报告已完成。完成后检查两个时间范围、任务影响、机会、风险与不确定性、行动建议和引用，并打开引用核对它属于该报告绑定的知识快照。

知识更新后需要重建；已有报告仍绑定生成时的快照。失败时记录失败阶段、封闭错误类别、重试次数和是否保存报告，不能把资料卡、阶段完成或单个接口返回成功当作整份报告通过。

## 可选的远程演示

先停止本地前台应用。远程脚本会启动并拥有它自己的本地应用进程，不会接管已有服务。

```bash
bash scripts/run-remote-demo.sh
```

脚本要求系统已安装 `cloudflared`，并且由真人在交互终端输入 `ENABLE REMOTE`。没有该确认便不会启动应用或 tunnel。它会等本次应用和两个模型就绪、核对监听进程，再启动指向 `127.0.0.1:8000` 的临时 tunnel。

成功取得临时地址后，脚本在终端显示地址。该地址公开可达，应用仍要求 CSV 登录；只向预定演示对象分享，使用合成或已脱敏的演示材料。这是私下演示，不是生产安全方案。取得地址也不等于远程登录、附件、进度和报告已经通过验收。

Cloudflare 官方说明 Quick Tunnel 不支持 SSE。当前界面已提供普通 HTTP 状态轮询：分析运行期间约每 5 秒重读状态，网络恢复或页面重新可见时也会恢复读取。远程演示可通过这一路径更新进度并读取最终报告；实际远程连接、刷新和结果恢复仍需单独验收，未实测时保持 PENDING。不能以本地结果替代远程验收。[Cloudflare Quick Tunnels 限制](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/)

已有 `~/.cloudflared/config.yaml` 或 `config.yml` 可能影响临时 tunnel；启动器会拒绝继续，由操作者自行检查，不会改名或覆盖原配置。

演示结束后运行：

```bash
bash scripts/stop-remote-demo.sh
```

脚本核对 `var/run/remote-demo.json` 中的 PID、用户、启动时间和完整命令，先停止 tunnel，再向本次应用发送正常退出信号。应用有时间取消自己的任务并清理自己的模型子进程。脚本不会按进程名称批量终止，也不会强制接管其他服务。

若身份不匹配或等待后仍未退出，脚本保留记录并返回失败；不要根据旧 PID 手动终止其他程序。稍后再次运行停止脚本并核查实际状态。全部退出后删除本次进程记录；`var/run/application.log` 和 `var/run/tunnel.log` 留在本机，可能包含临时地址，不要提交或分享整个日志。

## 保留内容和清理

候选人的原始上传文件使用 `var/tmp/uploads/` 临时目录。验收时应分别检查提取成功和提取失败后该目录是否还残留文件；不能因为界面关闭就推断文件已清理。

提取后的文字、消息、确认的资料卡、运行记录和报告保存在 `var/localcareerimpact.sqlite3`。知识原文件保存在 `data/knowledge/inbox/`，快照、分块和引用信息也在数据库中。删除原始候选人附件不会同时删除这些已提取内容。

需要完整清空本次演示数据时：

1. 停止远程和本地应用，确认它们与模型进程已退出。
2. 如需保留报告，先保存必要内容；完整清空会删除所有账户在此数据库中的会话、资料、运行记录、报告和知识快照。
3. 在文件管理器中删除 `var/localcareerimpact.sqlite3` 及同名 `-wal`、`-shm` 文件（如果存在），清理 `var/tmp/uploads/` 的残留；不要在应用运行时删除数据库。
4. 若也要删除知识原文件，单独清理 `data/knowledge/inbox/`；若保留知识原文件，重启后仍需重新重建知识库。
5. 如需删除演示日志，另行清理 `var/run/` 中的日志，先确认没有仍运行的已登记进程。

这些是完整重置步骤，不是逐条聊天删除。保留模型目录、依赖环境和本地账户/模型配置即可再次使用。实际清理结果填入验收记录，不能只记录“已运行清理命令”。

## 完成验收

使用 [验收记录](acceptance-record.md) 逐项记录实际观察。真实本地模型的一次完整运行、重复运行稳定性、远程体验和科学预测效果是不同结论，分别记录。尚未执行的项目保持 `PENDING`；失败保持具体失败阶段，不能用后续成功覆盖原失败证据。
